# Local Setup

This guide starts faynoSync on your machine so you can test application updates end to end: upload a build, publish it, and point your app's updater at it. No cloud account is needed — object storage is [Garage](https://garagehq.deuxfleurs.fr/), a lightweight S3-compatible server, preconfigured in the repository.

There are two ways to run it, and only a few steps differ between them — those steps have a tab for each:

- **Docker Compose**: the API, MongoDB, Redis and Garage all run as containers. Nothing to install except Docker. Choose this to try faynoSync or to test your app's updates against it.
- **From source**: MongoDB, Redis and Garage run in Docker Compose, while the API and the dashboard run from source with `go run` and `yarn dev`. Choose this to work on faynoSync itself. If you already run MongoDB, Redis and S3-compatible storage locally, you can use them instead of the containers.

Everything runs from the repository's own `docker-compose.yaml` and `.env.example`, so the configuration always matches the current release.

To deploy faynoSync on a server, see [Production Deployment](./production-deploy).

## 1. Clone the Repository

```bash
git clone https://github.com/ku9nov/faynoSync.git
cd faynoSync
```

## 2. Start the Services

<Tabs groupId="local-setup" queryString>
<TabItem value="compose" label="Docker Compose" default>

```bash
docker compose up --build -d
```

The first start builds the API image from source and bootstraps Garage (layout, access key, buckets, public website access). It takes a few minutes; later starts are fast. The API starts once MongoDB, Redis and Garage report healthy.

</TabItem>
<TabItem value="source" label="From source">

Start only the dependencies:

```bash
docker compose up -d db cache s3 webui
```

Naming the services starts only them, so the `backend` container does not start and port `9000` stays free for the API you run from source. Garage creates its buckets and access key on first start — wait until every service reports `healthy`:

```bash
docker compose ps
```

Then create the environment file:

```bash
cp .env.example .env
```

`.env.example` already holds working values for these containers (`localhost` for MongoDB and Redis, `127.0.0.1:3900` for the Garage S3 API). The API reads `.env` from its working directory; environment variables take precedence.

:::tip Using your own MongoDB, Redis and S3 storage

If you already run these locally, skip the compose command and point `.env` at them: `MONGODB_URL` (and `MONGODB_URL_TESTS` for the tests), `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, and the storage variables — `STORAGE_DRIVER`, `S3_API_ENDPOINT`, the access keys and bucket names. Create a public and a private bucket yourself; objects in the public bucket must be publicly readable. faynoSync is tested with MongoDB 7.0 and 8.0 and Redis 8.10. Every variable is described in [Environment Configuration](./env-overview).

:::

</TabItem>
</Tabs>

## 4. Start the API and Dashboard

<Tabs groupId="local-setup" queryString>
<TabItem value="compose" label="Docker Compose" default>

Nothing to do: the `backend` container is already running. The API is at http://localhost:9000 and serves the dashboard at http://localhost:9000/dashboard/.

</TabItem>
<TabItem value="source" label="From source">

Start the API:

```bash
go run faynoSync.go --loglevel=debug
```

It listens on http://localhost:9000. There is no hot reload for Go code: stop it and run the command again after a change.

In a second terminal, start the dashboard:

```bash
cd dashboard
yarn install
yarn dev
```

The dashboard runs on http://localhost:3000/dashboard/ with hot reload. The Vite dev server proxies every request outside `/dashboard/` to the API on port `9000`, so the dashboard and the API share one origin, as in production — no CORS configuration is needed. It also sends the same Content Security Policy as the API, so a resource blocked in production is blocked here too.

The API also serves a dashboard at http://localhost:9000/dashboard/, but that one is embedded into the binary at compile time from `server/dashboard/ui/dist` — the output of the last `yarn build`, not your current sources. Without a build it returns `503`. To check the production build, run `yarn build` in `dashboard/` and restart the API.

</TabItem>
</Tabs>

## 5. Create the Admin Account

Open the dashboard signup page — http://localhost:9000/dashboard/signup with Docker Compose, http://localhost:3000/dashboard/signup from source — and register. In the **Secret Key** field enter the `API_KEY` from `.env.example` — for the bundled configuration that is `insecure-dev-api-key`.

Or do the same through the API:

```bash
curl -X POST -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password", "api_key": "insecure-dev-api-key"}' \
  http://localhost:9000/signup
```

## 6. Check for an Update

After you [create an app](/docs/api/apps/create) and [upload a version](/docs/api/apps/upload), any client can ask for updates:

```bash
curl "http://localhost:9000/checkVersion?app_name=myapp&version=0.0.1&owner=admin"
```

Response formats are described in [Check Latest Version](/docs/api/info/latest).

## Services and Ports

| Service | Compose service | URL / port | Notes |
|---------|-----------------|------------|-------|
| FaynoSync API | `backend` | http://localhost:9000 | Container with Docker Compose, `go run` from source |
| Admin Dashboard | `backend` | http://localhost:9000/dashboard/ | Served by the API |
| Dashboard dev server | — | http://localhost:3000/dashboard/ | From source only (`yarn dev`) |
| MongoDB | `db` | `localhost:27017` | |
| Redis | `cache` | `localhost:6379` | Required: response cache, telemetry counters, TUF state, rate limits |
| Garage S3 API | `s3` | http://localhost:3900 | Access key and secret in `.env.example` |
| Garage website endpoint | `s3` | http://localhost:3902 | Serves public artifact links |
| Garage admin UI | `webui` | http://localhost:3909 | User `admin`, password `BjjctVsoSg4FKkT81VKt18` |

Public artifact links have the form `http://cb-faynosync-s3-public.web.garage.localhost:3902/<path>`. Browsers and `curl` resolve any `*.localhost` name to your machine, so these links open without editing `/etc/hosts`.

The configuration lives in the repository:

- `.env.example` — API environment (storage, Redis, telemetry, reports, TUF); Docker Compose reads it directly and overrides only the service hostnames in the `backend` service of `docker-compose.yaml`
- `docker-compose/configs/garage.toml` — Garage configuration
- `docker-compose/scripts/garage-entrypoint.sh` — Garage bootstrap

See [Environment Configuration](./env-overview) for every variable. The credentials in these files are for local testing only — never reuse them on a machine reachable from a network. `API_KEY` and `JWT_SECRET` use `insecure-dev-*` placeholders: the API logs a warning about them on every start and refuses to start with them when `GIN_MODE=release`.

The bundled configuration runs the API with performance mode, telemetry, reports and TUF enabled, so every feature is available locally.

## Running Tests

The integration tests need MongoDB, Redis and Garage running. Run the whole suite — the tests share state and depend on each other, so running a single test with `-run` is not supported.

<Tabs groupId="local-setup" queryString>
<TabItem value="compose" label="Docker Compose" default>

The API image ships the test binary. Wait until Garage finishes its bootstrap (`docker compose logs s3` shows `Garage bootstrap completed successfully.`), then run:

```bash
docker compose exec -T backend /usr/bin/faynoSync_tests
```

</TabItem>
<TabItem value="source" label="From source">

From the repository root:

```bash
go test
```

Unit tests:

```bash
go test ./server/... -race
```

</TabItem>
</Tabs>

## Troubleshooting

- **Port is already allocated** — another service uses one of the ports above. Stop it, or change the host side of the port mapping in `docker-compose.yaml`. From source, port `9000` is taken when the API container is running: stop it with `docker compose stop backend`.
- **`docker compose up` waits before starting the API** — the API starts only after MongoDB, Redis and Garage report healthy, and Garage turns healthy once its bootstrap (layout, key, buckets) has finished. Check progress with `docker compose ps` and `docker compose logs s3`.
- **The API run from source cannot connect to MongoDB, Redis or S3** — check that `.env` exists in the repository root and the containers are `healthy`.
- **`/dashboard/` on port 9000 returns `503` or shows an old UI** — from source, the API serves the dashboard embedded at compile time. Run `yarn build` in `dashboard/` and restart the API, or use the dev server on port `3000`.
- **Rebuilding the API image is slow** — with Docker Compose, every API change needs `docker compose up --build`. To work on faynoSync itself, run it from source.
